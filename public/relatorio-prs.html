O essencial, em 5 frases

    Uma entrega = um PR. PR é o pacote de código que alguém manda para entrar no sistema. Este relatório olha os pacotes do período e responde: quem entregou quanto, quem entrega pacotes maiores, e o que precisou voltar para conserto depois de pronto.

    O que voltou para conserto

    Aqui está a parte mais próxima de "erro" que dá para medir com honestidade.

    O que conta como conserto: uma entrega com a palavra fix que mexe na mesma área de uma entrega anterior. Exemplo real: o #210 consertou o #189, na área de mensagens, 3 dias depois. Nem todo conserto é erro — parte é melhoria e parte é problema que só aparece com o cliente usando. Mas quando muitos consertos caem na mesma área, ali tem um ponto fraco de verdade.

    Antes de usar estes números

    • Tamanho não é valor. Uma correção de 40 linhas que destrava um cliente vale mais que uma entrega de 2.000 linhas que só reorganiza arquivos. Nada aqui mede a importância do que foi feito.
    • Quem entrega mais aparece mais nos consertos. É aritmética, não descuido.
    • A conta simplex não é uma pessoa, é um login compartilhado. O que passa por ela fica sem dono.
    • 16% das entregas ficaram sem nome porque a branch foi apagada e não deu para saber quem fez. Elas contam no total, mas não nas linhas de cada pessoa.
    • Não existe teste automático rodando no período, então não dá para dizer quantas entregas quebraram algo — só quantas precisaram de conserto depois.
