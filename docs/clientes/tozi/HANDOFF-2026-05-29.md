## 7. O que está HARDCODED e precisa virar multi-cliente

Pra replicar pra outros clientes (Moreira, Midwest, etc.) sem retrabalho:

| Hoje (fixo) | Pra generalizar |
|---|---|
| `rake spx:tozi:*` (namespace tozi) | Já é parametrizável (account_id, inbox_id), mas namespace é tozi. Virar `spx:funnel:setup[account,inbox,nome]` genérico, ou config por cliente. |
| Funil "Pré-Venda Tozi" + 7 stages no código da rake | Mover definição de stages pra config/seed por cliente (YAML/DB), não hardcoded na rake. |
| Templates Tozi no `CADENCE_TEMPLATES` da rake | Templates por cliente — tabela/config, não constante Ruby. |
| Prompt da Júlia (nichos/empreendimentos Tozi) | Já é por-assistant (Scenario). OK — cada cliente tem seu assistant. Mas a knowledge (Playbook/FAQ) deve ser pipeline reproduzível por cliente. |
| `FunnelPlacementService` busca funil por automation_type | **Já é genérico** ✅ (acha funil que cobre a inbox + tem o stage). |
| Meta Lead Ads hook | **Já é genérico** ✅ (por page_id, multi-conta, multi-página). |
| Cadência (intervalos 2h/24h/3d) | Quando implementar Bloco 4, deixar intervalos/templates configuráveis por hook/cliente, não hardcoded. |

**Princípio:** o **mecanismo** (SPX) é genérico; a **configuração** (Tozi) deve virar dados por cliente, não código. Hoje a rake mistura mecanismo + dados Tozi — separar.
