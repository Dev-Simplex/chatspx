# Fixar conversa no topo da lista (por atendente)

**Nível:** júnior — mas é a volta completa da stack · **Risco:** baixo, isolado
**Onde validar:** staging antes da frota

---

## Por que esta task existe

Corretor de imobiliária acompanha dezenas de leads ao mesmo tempo. A lista de conversas
ordena por atividade, então **a conversa que ele mais precisa acompanhar afunda** assim que
qualquer outra recebe mensagem.

Hoje não existe forma de segurar uma conversa à vista.

## O que fazer

Um alfinete na conversa. Conversas fixadas aparecem no topo da lista **daquele atendente**.

> **A regra que manda em tudo:** é preferência **individual**, não estado compartilhado.
> Se virar flag global na conversa, um corretor fixa e bagunça a tela de todo mundo.
> Esse é o erro clássico dessa feature — é o que o review vai olhar primeiro.

## Onde mexer

Esta task passa por toda a stack, de propósito.

**1. Migration + model**

Tabela nova ligando atendente e conversa. Use `app/models/conversation_participant.rb`
como molde — ela já tem exatamente a forma necessária:

```ruby
validates :user_id, uniqueness: { scope: [:conversation_id] }
```

**2. Controller**

Um endpoint de liga/desliga (toggle).

**3. Ordenação**

`app/finders/conversation_finder.rb` — as linhas 6 a 9 mostram como as ordenações são
declaradas hoje (`last_activity_at_desc` e companhia). As fixadas sobem, e **entre elas a
ordenação normal continua valendo**.

**4. Frontend**

| Arquivo | O quê |
|---|---|
| `app/javascript/dashboard/components/widgets/conversation/ConversationCard.vue` | o botão de fixar |
| `app/javascript/dashboard/components/ChatList.vue` | a ordem da lista |

## Critério de aceite

1. Fixar coloca a conversa no topo **só para quem fixou** — outro atendente não vê diferença
2. Desfixar devolve à posição normal
3. Entre as fixadas, a ordenação por atividade continua valendo
4. Sobrevive a recarregar a página **e a trocar de máquina** (é dado no banco, não `localStorage`)
5. Um spec cobrindo o ciclo: fixa → lista → confirma o topo → desfixa → confirma que voltou
6. `rubocop` e `eslint` limpos nos arquivos tocados

## Pegadinhas conhecidas

- **Migration precisa ser reversível.** Testar `db:migrate` **e** `db:rollback`, não só o
  primeiro
- O factory `:channel_whatsapp` **sobrescreve** `provider_config` no `before(:create)`. Se o
  spec precisar de config específico, gravar depois com `update_column` — senão o teste passa
  por acidente
- O hook do `husky` quebra em worktree: `git commit --no-verify` se travar
- Nas VMs, `bundle` exige `bash -lc` (RVM)

## Fora de escopo

- Fixar para o time inteiro (é justamente o que **não** se quer)
- Limite de quantas conversas podem ser fixadas — deixar sem limite nesta primeira versão
- Ordenar as fixadas entre si por arraste
