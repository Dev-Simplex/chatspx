A lista de conversas parava em 25

Dois clientes relataram o mesmo defeito: o cabeçalho mostrava 84 conversas, a rolagem entregava 25 e anunciava “todas as conversas carregadas”. Corrigido e validado no staging; falta subir para a frota.

Origem: branch nicolas Destino: branch producao Data: 03/09/2026 Migration: nenhuma

Os dois commits, nesta ordem

O segundo depende do primeiro: ele troca a regra de fim de lista por um sinal explícito do backend, e essa regra só é segura sobre a ordenação estável que o primeiro introduz. Aplicar apenas um dos dois deixa o defeito de pé.

1º 78faf6d414fd74c343ebd6ac382cfa2e2392780b

fix(conversas): lista parava em 25 e conversas sumiam da rolagem

Desempate por id na ordenação, para casar com a tupla que o cursor compara — passa a usar o índice idx_conv_list_keyset, que já existia e estava ocioso. Cursor gravado em microssegundos em vez de milissegundos. Fim de lista deixa de ser inferido pela ausência de cursor. Abas IA e Aguardando ganham estado de paginação.

2º 5c74def397c4ea8655d67a97908ff12ed843cc83

fix(paginacao): backend passa a dizer se tem mais, e cursor para de comer microssegundos

O finder passa a devolver has_more nos dois modos de paginação e o front decide por ele. Elimina o laço infinito quando o total é múltiplo exato da página. Corrige a mesma truncagem de microssegundos em outros três cursores: Kanban, painel Ao Vivo e mensagens agendadas.

Há mudança de JavaScript, então um deploy sem assets:precompile entrega só metade da correção. O script de frota já faz isso; um deploy manual precisa fazer.

Como aplicar

Ramo a partir da produção

git fetch origin
git checkout -b spx/fix-rolagem-conversas origin/producao

Trazer os dois commits, na ordem

git cherry-pick 78faf6d414 5c74def397

Abrir o PR

git push -u origin spx/fix-rolagem-conversas
gh pr create --base producao \
  --title "fix(conversas): lista de conversas parava em 25 itens"
Atenção ao título

O CI reprova todo PR neste repositório; o único portão que vale é o Validate PR title, que exige Conventional Commits. Título fora do padrão trava o merge.

Deploy da frota

Depois do merge, rodar o deploy pelo orquestrador CHATSPX-PRODUCAO (192.168.8.229) — é o único host com credencial para o fan-out. O script já cuida de bundle install, pnpm install, assets:precompile, db:migrate e restart do chatwoot.target. 

./deployment/deploy.sh producao
Fora do fan-out

A VM TOZI não está no array de deploy por não ter credencial do GitHub — ela é atualizada à parte. Se for cliente afetado, precisa do passo manual.

Como conferir depois de subir

  • Entrar com um atendente que tenha ao menos uma conversa fixada e uma fila maior que 25. Rolar até o fim: a contagem tem de bater com o número do cabeçalho, e o aviso de fim de lista só aparecer no fim de verdade.
  • Repetir nas abas Minhas e Não atribuídas — elas eram contaminadas por um falso fim na aba Todas.
  • Trocar a ordenação para prioridade e abrir uma pasta ou filtro salvo: eram os outros dois gatilhos.
  • No Kanban, abrir uma coluna com mais de 30 cards e rolar até o fim. Vale só nas contas com kanban_cursor_loading ligada.
  • Na resposta de GET /conversations, o campo meta.has_more passa a existir. É acréscimo, não quebra contrato.

O que ficou de fora

Registrado e não incluído nestes commits, para não misturar escopo: com filtro de período ativo, o contador do cabeçalho ignora o recorte de data enquanto a lista o aplica; e em pastas filtradas por etiqueta a contagem infla quando a conversa tem várias etiquetas. São defeitos de contador, de origem diferente, e não afetam a rolagem.

Validado no staging nicolas.chatspx.app com 11 verificações automatizadas em duas contas — 84 e 300 conversas, com horários deliberadamente empatados — todas sem perda e sem repetição. Nenhum teste foi feito em produção.
